# 建模线实验数据后处理

跑完后的 `runs/` 不进 Git。后处理只读这些目录，写出表格。

一条 run 要同时有 `evaluation.json` 和 `manifest.json` 才会进入汇总。`runs/archive/` 里的旧尝试不统计。

## 导出 Excel

在仓库根目录执行：

```powershell
uv run python scripts/export_results_xlsx.py `
  --runs-dir runs\formal-run `
  --output runs\formal-run\experiment_results.xlsx
```

不传 `--output` 时，文件写到该运行目录下的 `experiment_results.xlsx`。

工作簿主要包括：

| 表 | 内容 |
| --- | --- |
| 父仓库规则对照 | 编译、结构、构造正确性、文本相似度、耗时、资源消耗、加权综合分 |
| 每桥型 | 按桥型拆开的分数 |
| 分组汇总 | 按架构、桥型、任务形式的均值 |
| 运行明细 | 每一条 run 的原始分数 |
| 结果目录 | 结果在磁盘上的位置 |
| 失败汇总 | 失败类型和次数 |
| 冻结配置 | 这次实验锁定的模型与配置 |
| 说明 | 评分口径 |

均值只对有正式评分、且没有被标成基础设施失败的 run 计算。失败 run 不从成功率的分母里拿掉。

## 其他处理

已有结果需要按当前评分代码重算时：

```powershell
uv run python scripts/rescore_runs.py --runs-dir runs\formal-run
```

查看进度：

```powershell
uv run python scripts/progress_board.py --label formal-run
```

检查运行目录有没有把答案混进模型输入：

```powershell
uv run python scripts/audit_external_dirs.py
uv run python scripts/audit_no_cheating.py
```

生成的 xlsx 留在 `runs/` 里，不要提交。
