# T4 原生技能优化与重跑协议

## 目标

T4 应测量 OpenHands 自身的 AgentSkills、Think/Finish 工具与 Conversation 循环。旧适配器虽然加载了原生技能，同时又把完整技能索引、案例目录和文件目录注入共享 prompt，并暴露通用 read_skill 入口。模型可以绕过原生技能调用，长目录和参考读取也会放大上下文。

## 适配器 v2

1. 使用 OpenHands 1.44.1 的 load_skills_from_dir 和 AgentContext 挂载冻结快照。
2. 精简任务 hand-off，只包含完整 TaskSpec、13 文件合同和执行顺序，明确先调用 SDK 原生 invoke_skill。
3. 移除 list_skills、read_skill 和 search_skill_cases 自定义旁路。
4. 保留参考读取、知识库、候选读写与完整性检查，并增加候选文件枚举和 Python 语法检查。
5. 将事件写入 t4_events.jsonl，只保存事件类型、工具名、调用 ID、响应 ID 和技能名，不保存思维正文或大段工具输出。
6. generation 元数据记录 native_skill_invocations、tool_call_counts、prompt 长度与自定义工具清单。

## 重跑公平性

旧结果保留，v2 使用新的 campaign label，不覆盖任何 run。重跑必须固定：

- 与原 T4 相同的数据矩阵、TaskSpec、train-all 技能快照哈希和父仓库 commit；
- 相同模型、variant、温度、token/step/总时限和 seed；
- 相同 PyOSIS 生成后门禁、CLI 评分器、官方评价和结果导出流程；
- 唯一实验变量为 T4 适配器实现版本。

先运行一条 full smoke。检查生成元数据中 native_skill_invocations 非空、事件轨迹存在、候选文件有写入、静态/运行门禁能继续执行。Smoke 通过后再运行 T4 的完整 full/gen/edit 矩阵。

## 对比报告

新旧 T4 分开汇总。报告至少包含完成率、候选文件数、原生技能调用率、模型/工具调用数、输入与输出 token、耗时、静态分、运行分和官方评分。基础设施故障单列，不计入能力得分。
