# T1–T6 框架使用说明

六个架构使用同一份任务、同一份无测试答案技能快照、同一个模型网关、同一套 PyOSIS 执行器和同一套父仓库评分器。比较变量是生成阶段的编排方式。

## 共同入口

单个任务都通过统一驱动运行，只有 `--architecture` 不同：

```powershell
uv run python scripts/run_dataset.py `
  --architecture T2 `
  --bridge osis-bridge-cantilever-box `
  --form full `
  --index 0 `
  --seed 0 `
  --parent-repo $env:OSIS_PARENT_REPO
```

正式运行默认执行 PyOSIS 建模、`engine.solve()` 和父仓库正式评分。`--no-solve-gate` 和 `--no-pyosis` 只用于诊断，不能与正式结果混合统计。

批量运行推荐使用：

```powershell
uv run python scripts/run_campaign.py `
  --label formal-run `
  --auto-forms `
  --resume `
  --parent-repo $env:OSIS_PARENT_REPO `
  --jobs 3
```

调度器会让 T1–T5 并行，T6 串行运行。已经有 `evaluation.json` 和 `manifest.json` 的 run 会被 `--resume` 跳过。

## T1：direct one-shot

- **环境**：`.venvs/main`。
- **调用方式**：一次 OpenAI-compatible 模型请求。
- **工具交互**：模型不运行 Agent 工具循环；技能索引、项目画像和必要参考内容在请求前整理进提示词。
- **适用目的**：测量没有工具调用和自我修正能力的一次性生成基线。
- **输出**：模型返回的文件块被解析到 `candidate_project/`。

```powershell
uv run python scripts/run_dataset.py --architecture T1 `
  --bridge osis-bridge-cantilever-box --form full --index 0 `
  --parent-repo $env:OSIS_PARENT_REPO
```

## T2：LangGraph / LangChain ReAct

- **环境**：`.venvs/main`。
- **调用方式**：LangGraph 状态图驱动 ReAct 循环。
- **工具交互**：模型按需读取技能、参考资料、任务文件和候选文件，并调用写文件、完整性检查和知识库检索工具。
- **适用目的**：测量显式“思考 → 工具 → 观察 → 修改”循环的效果。
- **输出**：`candidate_project/` 和 `generated/t2_transcript.jsonl`。

```powershell
uv run python scripts/run_dataset.py --architecture T2 `
  --bridge osis-bridge-cantilever-box --form full --index 0 `
  --parent-repo $env:OSIS_PARENT_REPO
```

## T3：smolagents CodeAct

- **环境**：`.venvs/t3`。
- **调用方式**：smolagents `CodeAgent`。
- **工具交互**：模型通过受限工具读取技能和候选文件，并生成可执行的 Python 操作代码。
- **适用目的**：测量 CodeAct 编排方式在工程写入和自我修正中的效果。
- **输出**：`candidate_project/` 和 `generated/t3_generation.json`。

```powershell
uv run python scripts/run_dataset.py --architecture T3 `
  --bridge osis-bridge-cantilever-box --form full --index 0 `
  --parent-repo $env:OSIS_PARENT_REPO
```

## T4：OpenHands CodeAct

- **环境**：`.venvs/t4`。
- **调用方式**：OpenHands SDK `AgentContext + Agent + Conversation`。
- **技能机制**：用 `load_skills_from_dir` 挂载同一快照，由 SDK 原生 `invoke_skill`
  渐进加载技能正文；任务提示不再重复注入技能索引和全部案例/文件清单。
- **工具交互**：保留参考文件、知识库和候选工程读写能力，增加候选文件枚举与 Python
  语法检查；候选完整性仍由统一工具检查。
- **适用目的**：测量 OpenHands 原生技能路由、思考工具和 CodeAct 会话的效果。
- **审计输出**：`candidate_project/`、`generated/t4_generation.json` 和不含思维正文的
  `generated/t4_events.jsonl`。事件轨迹记录工具名、响应 ID 和原生技能调用。

```powershell
uv run python scripts/run_dataset.py --architecture T4 `
  --bridge osis-bridge-cantilever-box --form full --index 0 `
  --parent-repo $env:OSIS_PARENT_REPO
```

## T5：CrewAI 角色协作

- **环境**：`.venvs/t5`。
- **调用方式**：CrewAI 三角色串行协作。
- **角色分工**：研究员读取技能和案例，工程师生成候选工程，审查员检查完整性并推动修正。
- **适用目的**：测量角色分工和多阶段协作的效果。
- **输出**：`candidate_project/` 和 `generated/t5_generation.json`。

```powershell
uv run python scripts/run_dataset.py --architecture T5 `
  --bridge osis-bridge-cantilever-box --form full --index 0 `
  --parent-repo $env:OSIS_PARENT_REPO
```

## T6：OSIS-AI 原生编排

- **环境**：父仓库 `.venv`，以及外部 OSIS 求解器和 OpenCode 安装。
- **调用方式**：启动隔离的 OpenCode 服务，通过父仓库 `opencode_client` 建立原生会话。
- **工具交互**：使用 OSIS-AI 原生 `AGENTS.md` 工作流和挂载的 `train-all` 技能快照。
- **特殊限制**：OSIS 引擎是进程级单例，正式批量运行时 T6 必须串行；不要手工并发启动多个 T6 run。
- **输出**：`candidate_project/`、T6 会话日志和 OpenCode 审计产物。

```powershell
uv run python scripts/run_dataset.py --architecture T6 `
  --bridge osis-bridge-cantilever-box --form full --index 0 `
  --parent-repo $env:OSIS_PARENT_REPO
```

T6 还需要配置 `OSIS_OPENCODE_DIR`、`T6_AI_PORT`、OSIS 求解器目录和父仓库 `.venv`。这些商业或机器相关组件不随仓库提交，详见 [`ENVIRONMENT.md`](../ENVIRONMENT.md)。

## 统一输出和评分

所有架构最终都必须生成相同的 `candidate_project/py/prep/` 工程。框架本身不负责正式评分；外层运行器统一执行：

1. 工程结构检查和 Python 编译；
2. PyOSIS 建模、验证和求解；
3. 父仓库 `src/evaluation` 六项评分；
4. 运行态测量、Token 统计和结果表格导出。

因此，T1–T6 的差别只体现在生成阶段，不应使用某个框架自带的额外评分器替代父仓库评分。
