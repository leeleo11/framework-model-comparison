# 建模线实验使用说明

比较 T1–T6 在同一批建模任务上的差别。任务、技能快照、模型和评分器相同，变的是各框架自己的编排。环境用 `uv` 安装，不要把 `.venv` 或 `.venvs` 提交进仓库。安装步骤见 [ENVIRONMENT.md](../ENVIRONMENT.md)。

先设好父仓库和模型网关：

```powershell
$env:OSIS_PARENT_REPO = "C:\path\to\osis-skill-enhance-main"
$env:OSIS_MODEL_API_KEY = "<key>"
$env:OSIS_MODEL_BASE_URL = "http://<gateway>/v1"
```

## 怎么开跑

一条任务，只改 `--architecture`：

```powershell
uv run python scripts/run_dataset.py `
  --architecture T2 `
  --bridge osis-bridge-cantilever-box `
  --form full `
  --index 0 `
  --seed 0 `
  --parent-repo $env:OSIS_PARENT_REPO
```

`--form` 取 `full`（整桥）、`gen`（补模块）或 `edit`（改已有工程）。正式运行会做 PyOSIS 建模、`engine.solve()` 和父仓库评分。`--no-pyosis`、`--no-solve-gate` 只用于排查，不能和正式分数混在一起。

整表对比：

```powershell
uv run python scripts/run_campaign.py `
  --label formal-run `
  --auto-forms `
  --resume `
  --parent-repo $env:OSIS_PARENT_REPO `
  --jobs 3
```

`--auto-forms` 按 `full → gen → edit` 跑，可断点续跑。`--resume` 跳过已有 `evaluation.json` 和 `manifest.json` 的 run。

## 并行还是串行

OSIS 求解器是本机单例，默认端口 18080。T1–T5 的生成可以并行，`--jobs` 默认 3；求解和评分会在仓库锁上排队。T6 独占 OpenCode 和求解器，campaign 把 T6 放在每阶段最后，严格串行。不要同时手工启动多个 T6，也不要和验算修复的正式求解一起占 18080。

网关在主机 CPU 约超过 90% 时会返回 503。并行过高时把 `--jobs` 降到 1。

结果在 `runs/<label>/`。汇总表：

```powershell
uv run python scripts/export_results_xlsx.py --runs-dir runs\<label>
```

## T1–T5

六个架构的环境由 `uv run python scripts/setup_framework_envs.py` 创建。T1、T2 用 `.venvs/main`，T3–T5 用各自的 `.venvs/t3`、`t4`、`t5`。驱动脚本会按架构选解释器，不用手切环境。

| 架构 | 环境 | 动作 | 技能怎么给 | 候选工程怎么写 |
| --- | --- | --- | --- | --- |
| T1 | `.venvs/main` | 一次 `/chat/completions`，没有工具循环 | 技能索引和所需参考在请求前写入提示词 | 解析回复里的 `### FILE:` 块 |
| T2 | `.venvs/main` | LangGraph `create_agent`，JSON 工具调用 | `list_skills`、`read_skill`、`read_skill_reference`、`list_reference_files`、`search_skill_cases` | `read_candidate_file`、`write_file` |
| T3 | `.venvs/t3` | smolagents `CodeAgent`，动作用 Python | `tools=[]`。解释器放行 `json`、`pathlib`，自己读快照 | 用 `pathlib` 写入 `candidate_project/` |
| T4 | `.venvs/t4` | OpenHands 默认智能体 | `load_skills_from_dir`，先 `invoke_skill` | 官方终端和文件编辑器。浏览器关闭 |
| T5 | `.venvs/t5` | CrewAI 三角色：研究员、工程师、审查员 | `Crew(skills=...)` 的 `load_skill`。参考文件用 `read_skill_resource` | 官方 `FileReadTool` / `FileWriterTool`，限制在候选目录。`allow_delegation=True` |

T2 必须由调用方传入工具，空工具列表就只剩语言模型。T3 不注册自建读写函数；网关若把动作包成 DSML，只在模型边界还原成 `<code>`，代码本身不改。T5 的 `load_skill` 只返回 `SKILL.md`，所以才有 `read_skill_resource`。代码解释器保持关闭，这个工具在 CrewAI 里已经废弃。

T2–T5 在同一次 run 里可以根据编译和建模失败再改一版。T1 没有这个循环。

单架构命令把上面的 `T2` 换成 `T1`、`T3`、`T4` 或 `T5` 即可。

## T6

T6 用父仓库 `.venv`、OpenCode 和 OSIS 求解器，在隔离工程里挂同一份技能快照，权限不做裁剪。不要和 T1–T5 并行启动。端口默认 `T6_AI_PORT=4097`。
