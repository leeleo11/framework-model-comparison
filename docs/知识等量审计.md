# 知识等量审计（论文附录）

对应设计原则 3.1 ③：领域知识用各框架自己的官方方式注入（SKILL/提示词等），内容一字不差，等价性在此审计说明。

## 统一知识源

所有六框架挂载同一个无泄漏快照：

```text
checkpoints/train-all/skills
  sha256 = e19125d08827131fc22d15f8e54381857e3bf91fbc71254c3fdf72f77e69ef5a
  28 个 skill、991 个文件、63 个 train 模板、0 个 test 模板（SKILL 正文 test 名已清洗）
```

- 内容**字节级确定**：`scripts/build_train_all_snapshot.py` 生成 + manifest 记录全量文件哈希，任何框架读到的都是同一份字节。
- **原始 `.agents/skills`（含 test 答案）对全部框架物理不可达**：`_resolve_skills_dir` 拒绝；各框架的挂载根都在快照内。

## 各框架注入方式（机制各异，内容同源）

| 框架 | 注入机制 | 内容来源 | 说明 |
|---|---|---|---|
| **T1** | 一次性知识包进 prompt | `SkillAdapter`(快照) 读取 | ⚠️ 受 prompt 预算(100k 字符)限制，注入 SKILL 正文+visible 模板+exemplar 的**子集**——见下方注意 |
| **T2** | 系统提示(技能索引+案例清单+文件清单) + 8 工具按需读 | `SkillAdapter`(快照) | 全量可读，按需检索 |
| **T3** | prompt(同 T2) + 8 工具按需读 | `SkillAdapter`(快照) | 同上 |
| **T4** | prompt(同 T2) + 8 工具按需读 | `SkillAdapter`(快照) | 同上 |
| **T5** | prompt(同 T2) + 8 工具按需读 | `SkillAdapter`(快照) | 三角色共用 |
| **T6** | 快照考入隔离 `.agents/skills`（openode 原生技能目录） | 快照复制 | 与 T2–T5 内容一致的**全部** 28 skill |

## 工具集等量（3.1 ②，配套审计）

T2–T5 统一暴露**同名同 8 工具**：

```text
list_skills / read_skill / read_skill_reference / list_reference_files /
search_skill_cases / write_file / read_candidate_file / check_project_completeness
```

来源 `baselines/_framework_common.py`（共享实现），各框架以官方方式注册（LangGraph BaseTool / smolagents @tool / openhands Action-Observation / crewai @tool）。T1=无工具 one-shot、T6=OSIS-AI 原生工具，为两端 anchor。

## 等价性论证

1. **同一份字节**：六个框架从同一个 sha256 钉死的快照取知识（T1/T2 读；T3/T4/T5 读；T6 复制快照）。
2. **机制不同但内容不缩水**：
   - T2–T5 的工具能读取**任意**快照文件（含全部 63 模板 + SKILL 正文），`list_reference_files` 消除"猜路径"差异 → 信息完全等量。
   - T6 直接挂载全部 28 skill（内容 = 快照全量）。
   - T1 的一次性知识包是**预算受限子集**（SKILL 正文 + 最近 visible 模板 + exemplar，100k 字符封顶）——这是 T1"无循环"范式的固有权衡，已在文档/运行记录标注，不视为等量缺失（其基线定位即"最弱单次注入"）。

## 已知边界

- T1 知识包 = 子集（范式固有权衡，上面说明）。
- T6 用 OSIS-AI 原生工具（shell/ls/copy），工具集不等于 harness 8 件套——这是"框架=变量"的构成部分，非知识不等量。
- 本审计随快照重建/参数变更需更新（sha256 变了就重出）。
