# 知识等量审计（论文附录）

对应设计原则 3.1 ③：领域知识用各框架自己的官方方式注入（SKILL/提示词等），内容一字不差，等价性在此审计说明。

## 统一知识源

所有六框架挂载同一个无泄漏快照：

```text
checkpoints/train-all/skills
  sha256 = e19125d08827131fc22d15f8e54381857e3bf91fbc71254c3fdf72f77e69ef5a
  28 个 skill、991 个文件、63 个 train 模板、0 个 test 模板（SKILL 正文 test 名已清洗）
```

- 内容**字节级确定**：`scripts/build_train_all_snapshot.py` 生成 + manifest 记录全量文件哈希，任何框架读到的都是同一份字节。
- **原始 `.agents/skills`（含 test 答案）对全部框架物理不可达**：`_resolve_skills_dir` 拒绝；各框架的挂载根都在快照内。

## 各框架注入方式（机制各异，内容同源）

| 框架 | 注入机制 | 内容来源 | 说明 |
|---|---|---|---|
| **T1** | 一次性知识包进 prompt | `SkillAdapter`(快照) 读取 | ⚠️ 受 prompt 预算(100k 字符)限制，注入 SKILL 正文+visible 模板+exemplar 的**子集**——见下方注意 |
| **T2** | 系统提示给出技能索引和可见模板名；读工具按需读取快照 | 适配器工具读同一快照 | 不预载模板内文件路径，不接知识库 |
| **T3** | 提示给出技能目录绝对路径；`CodeAgent` 用放行的 `pathlib` 读取 | 解释器直接读同一快照 | 放行 `pyosis`。只链接父仓库里的纯 Python 包，不把整个 3.11 环境放进 T3。不注册自建运行工具 |
| **T4** | OpenHands `AgentContext` + 原生 `invoke_skill` | 同一快照经 SDK 原生 loader 读取 | 写文件用官方 `terminal` / `file_editor` |
| **T5** | `Crew(skills=...)` 挂载快照，角色调用 `load_skill` | CrewAI 原生技能加载同一快照 | 工程师用 `FileWriterTool` 写候选工程，审查员只读。工具的 `base_dir` 限制在候选工程内 |
| **T6** | 快照考入隔离 `.agents/skills`（openode 原生技能目录） | 快照复制 | 与 T2–T5 内容一致的**全部** 28 skill |

## 能力等量（3.1 ②，配套审计）

动作接口按各框架自己的官方方式保留，原因和「为什么只给 T3 接 pyosis」写在 [框架使用说明.md](框架使用说明.md)。T2 的 `create_agent` 不自带工具，调用方只交读技能和写候选工程。T3 的动作是 Python 解释器，`pyosis` 放进允许导入名单；父仓库是 Python 3.11，所以只链接纯 Python 的 `pyosis`，不把整个环境放进 T3。T4 用官方 `invoke_skill`、`terminal` 和 `file_editor`。T5 用 `load_skill`、委托和 `FileWriterTool`，代码执行关闭。不另做共用的运行工程工具。交卷后不再把编译或建模报错送回。正式 PyOSIS 只在评分时跑一次。

## 等价性论证

1. **同一份字节**：六个框架从同一个 sha256 钉死的快照取知识（T1/T2 读；T3/T4/T5 读；T6 复制快照）。
2. **机制不同但内容不缩水**：
   - T2 通过绑定的读工具读取快照；T3 通过 `pathlib` 读取同一目录；T4 由 `invoke_skill` 读取同一批技能；T5 通过 `load_skill` 读取同一批 `SKILL.md`。
   - T6 直接挂载全部 28 skill（内容 = 快照全量）。
   - T1 的一次性知识包是**预算受限子集**（SKILL 正文 + 最近 visible 模板 + exemplar，100k 字符封顶）——这是 T1"无循环"范式的固有权衡，已在文档/运行记录标注，不视为等量缺失（其基线定位即"最弱单次注入"）。

## 已知边界

- T1 知识包 = 子集（范式固有权衡，上面说明）。
- T6 用 OSIS-AI 原生工具（shell/ls/copy）。它和 T2 的绑定工具、T3 的解释器、T4 的终端与文件编辑器、T5 的 `load_skill` 不是同一套工具，这是框架变量，不是知识不等量。
- 本审计随快照重建/参数变更需更新（sha256 变了就重出）。
