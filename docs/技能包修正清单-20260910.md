# 技能包修正清单（供人工审核）

**背景**：2026-09-10 六架构对比实验中，T2/T3/T4/T5 四个架构失败，根因全部指向**技能包内容与运行时不一致**。
本清单给出每条缺陷的**证据**与**已实测验证的修法**，供你审核后决定是否修改父仓库。

**验证环境**：`osis-skill-enhance-main/.venv`（pyosis 0.6.4），后端 18080。
**重要**：下列写法我均已实测通过；但**改动的是权威源**，请逐条确认后再动手。

## 缺陷 1：`create_rect` 参数签名不完整（导致 T2/T3 失败）

### 现状

`ossis-python-helper/SKILL.md:310`：

```
| `create_rect(no, name, h, b)` | 矩形 |
```

### 问题

运行时真实签名（pyosis 0.6.4，`pyosis/section/manager.py:1338`）：

```python
create_rect(no, name,
            transition_type: Literal['Chamfer','Fillet'] = 'Fillet',
            sec_type: Literal['Solid','Hollow'] = 'Solid',
            b: float = 6.5, h: float = 3.2,
            xo1, yo1, r, t1, t2, xi1, yi1, has_diaphragm, tw,
            xi2, yi2, has_groove, b1, b2, h_groove)
```

文档省略了 `transition_type` 和 `sec_type`，并把 `b, h` 提到了第 3、4 位。
模型照文档写 `create(2, "桥墩截面", "RECT", 7.0, 2.5)` → `7.0` 落到 `transition_type`（应为字符串）
→ 后端报 `第4个参数输入有误`。

**复现确认**：我用文档写法直接调用，产出的报错与 T2/T3 的 `build_stderr.log` **逐字相同**。

### 建议修法（二选一，均已实测通过）

**方案 A：关键字传参（推荐，最不易错）**

```python
engine.section.create(2, "桥墩", "RECT",
                      transition_type="Chamfer", sec_type="Solid",
                      b=2.5, h=7.0)
```

**方案 B：完整位置传参**（模板现有写法，21 个参数）

```python
engine.section.create(2, "桥墩", "RECT", "Chamfer", "Solid",
                      7.0, 2.5, 1.0, 0.5, 0.0, 1.0, 1.0, 0.5, 0.25, 0,
                      1.0, 0.5, 0.25, 1, 1.2, 0.8, 0.2)
```

> 注意方案 B 中第 6、7 位是 `b=7.0, h=2.5`（宽、高），**不是文档说的 `h, b`**。

### 建议改动

把 `osis-python-helper/SKILL.md:310` 那一行补全为真实签名，或至少注明
"前两个位置参数是 `transition_type`/`sec_type`，之后才是 `b`(宽) `h`(高)"。

## 缺陷 2：`create_spring` 参数名跨版本不一致（导致 T4 失败）

### 现状

- `osis-module-element/SKILL.md:65,77,221`：`bLinear=1`
- `osis-python-helper/SKILL.md:324`：`element.create_spring(no, node1, node2, bLinear=1, ...)`

### 问题

| 版本 | 第 4 个参数名 | 出现在 |
|---|---|---|
| 0.6.4（**harness 执行候选工程用的**） | `is_linear` | `.venv`、`~/.osisai/.venv` |
| 0.5.2（OSIS 应用侧自带 Python311） | `bLinear` | `Rbin64(1)/Python311` |

文档按 0.5.2 写的，但候选代码由 **0.6.4** 执行 → `TypeError: unexpected keyword argument 'bLinear'`。

**实测**：`is_linear=1` 在 0.6.4 下 OK；`bLinear=1` 报 TypeError。

### 建议修法（实测通过）

**推荐：位置传参**（跨两个版本都可用，模板里也是这么写的）

```python
engine.element.create_spring(no, node1, node2, 1, 1e13, 1e13, 1e13, 1e16, 1e16, 1e16)
#                                      ↑ 线性标志位，无需写参数名
```

**或关键字传参（仅 0.6.4）**

```python
engine.element.create_spring(no, node1, node2,
                             is_linear=1, dx=1e13, dy=1e13, dz=1e13,
                             rx=1e16, ry=1e16, rz=1e16)
```

### 建议改动

1. `osis-module-element/SKILL.md`：`bLinear` → `is_linear`，并注明"应用侧旧版为 `bLinear`，建议位置传参以兼容"；
2. `osis-python-helper/SKILL.md:324`：同上。

## 缺陷 3：模板含后端不支持的命令（导致 T5 失败）

### 现状

`osis-bridge-cantilever-box/references/templates/变截面悬浇连续梁-30+50+30/prep/_4_section.py:19-29`
（11 行）：

```python
engine.section.get(2).set_stress_point(2, -2.5, -1.25)
engine.section.get(2).set_stress_point(3, 2.5, 1.25)
... 共 11 行
```

### 问题

`set_stress_point` 在 pyosis **两个版本中都存在**，签名也都是 `(n_point, x, y)`，
`pyosis_doc.py lookup set_stress_point` 能正常查到。

**但 OSIS 后端拒绝 `StressPoint` 命令**，且返回**空错误信息**：

```
设置截面 2 应力点 2 失败: 命令流中第1句"StressPoint,2,2,-2.5,-1.25"命令错误如下：
                                                                    ↑ 后面没有内容
```

**实测矩阵**（我逐项验证）：

| 环境 | pyosis | 参数组合 | 结果 |
|---|---|---|---|
| harness `.venv` | 0.6.4 | n_point 1/2/3 × 坐标 (0,0)/(1,0.5)/(-2.5,-1.25)/(0.5,0.5) | **全部失败** |
| 应用侧 `Rbin64(1)/Python311` | 0.5.2 | 同样组合 | **同样失败** |

→ 不是 pyosis 版本问题，是**后端能力缺口**。

**影响**：任何模型只要抄这个模板的 `_4_section.py`，必然在建截面阶段死掉。T5 就是这么死的。

### 建议修法（实测通过）

**直接删除这 11 行**——我验证过，截面**不设自定义应力点照样可用**：
跳过 `set_stress_point` 后 `section.count()` 正常返回，后续单元/边界/荷载建模不受影响。

自定义应力点是可选优化，不是建模必需。

### 建议改动（三选一）

- **A（推荐）**：从模板中删除这 11 行，并加一行注释说明"本后端不支持自定义应力点，已省略"；
- **B**：保留但整体注释掉，注明原因；
- **C**：如果**确认该后端应该支持**，这是 OSIS 后端 bug，应报给 OSIS 开发，技能包暂时规避。

## 影响评估（修不修的后果）

| 缺陷 | 不修的后果 |
|---|---|
| 1（`create_rect`） | T2/T3 类 ReAct 架构会持续按文档写错，**分数被系统性压低** |
| 2（`create_spring`） | T4 同样持续失败 |
| 3（`set_stress_point`） | 任何抄该模板的架构（含 T1/T6）都可能死 |

**对实验结论的影响**：当前 T6 的领先（构造分 0.965 vs T2–T5 的 0.35–0.5）含有
"T6 选的模板恰好避开了这三个雷区"的成分，**不能直接读作架构能力差异**。
修完这三条后重跑，结论才站得住。
